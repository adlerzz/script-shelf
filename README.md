# Script Shelf

Chrome-расширение для хранения и ручного запуска JavaScript на текущей вкладке.

## Сборка и установка

1. Распакуй архив проекта, выполни `npm ci` и `npm run build`. Архив содержит исходники без `dist`.
2. Открой `chrome://extensions`, включи **Режим разработчика**.
3. Нажми **Загрузить распакованное расширение** и выбери папку **dist**.
4. В Chrome 138+ открой **Подробнее** у Script Shelf и включи **Разрешить пользовательские скрипты / Allow User Scripts**. В Chrome 135–137 достаточно режима разработчика.
5. Закрепи расширение на панели. Открой обычную веб-страницу и нажми его иконку.
6. **Управление** открывает редактор. Создай скрипт, сохрани его; затем запусти из popup на нужной вкладке.

Минимальная версия Chrome — 135. Другие Chromium-браузеры должны поддерживать `chrome.userScripts.execute`; совместимость с ними отдельно не проверялась. Для файлов `file://` включи **Разрешить доступ к URL файлов** в деталях расширения. Встроенные страницы браузера и Chrome Web Store не допускают инъекцию.

## Сборка и проверки

Требуется Node.js 22.13+ (или более новая LTS-версия).

```sh
npm ci
npm run build
```

`npm run build` проверяет TypeScript и Svelte-компоненты через `svelte-check`, очищает `dist`, собирает ES-модули Rollup и копирует HTML/CSS/manifest/icons. Карты исходников не создаются. Собранная папка `dist` готова для загрузки в Chrome как распакованное расширение.

UI написан на Svelte 5 с TypeScript. Код проверяется и оформляется ESLint с `typescript-eslint`, `eslint-plugin-svelte` и `@stylistic/eslint-plugin`. Все настройки находятся в `eslint.config.mjs`; отдельного форматтера нет. Rollup собирает модули в `dist/` без минификации.

```sh
npm run lint      # проверить код и оформление TS/JS/Svelte
npm run lint:fix  # автоматически исправить поддерживаемые правила
```

Стиль по примеру авторского кода: 4 пробела, преимущественно двойные кавычки, точки с запятой, `function name (arg)`, стрелочные параметры без скобок при возможности (`item => ...`), обязательные фигурные скобки и многострочные тела блоков. Пробелы в вызовах — `fn(arg)`, в условиях — `if (condition)`, в блоках — `if (condition) { ... }`.

Переносы строк, длина строки и завершающие запятые оставлены на усмотрение автора: ESLint не навязывает для них формат. HTML, CSS и JSON сохраняют своё текущее оформление и не входят в эту TS/JS/Svelte-конфигурацию ESLint.

Компоненты используют `$state`, `$derived`, `$props`, `bind:value`, `{#each}` и рекурсивный snippet для дерева. Состояние формы хранится в компоненте; в Chrome API передаются обычные DTO. `src/popup.ts` и `src/manager.ts` только монтируют корневые компоненты. Service worker, модель данных и запуск скриптов остаются обычными TS-модулями.

Стили дерева, иконок, редактора, шапки, строки статуса и раскладки страниц находятся в `<style>` соответствующих Svelte-компонентов и ограничены их областью. Вложенные селекторы, модификаторы, псевдоклассы и локальные `@media` записаны с нативным CSS nesting. `public/styles.css` содержит только общую тему, сброс и базовые правила для элементов управления. Rollup включает стили компонентов в JavaScript; Svelte добавляет их при монтировании.

Для редактора рекомендуется расширение **Svelte for VS Code**.

Браузерная регрессионная проверка (Chrome API замоканы):

```sh
npx playwright install chromium
npm run build
npm run test:ui
```

Можно использовать уже установленный Chromium через переменную `SHELF_BROWSER_EXECUTABLE` с путём к исполняемому файлу. Проверка не запускает расширение как установленное: она тестирует собранные страницы, реактивные поля, дерево, импорт/экспорт и обмен DTO. `npm run check` не требует браузера.

Короткие действия через `condition && action()` разрешены правилом `@typescript-eslint/no-unused-expressions`.

Для изменения оформления правь объект `styleRules` и правило `curly` в `eslint.config.mjs`. `npm run check` запускает ESLint, проверку TypeScript, сборку и тесты.

## Возможности

- Popup: дерево папок, сворачивание, поиск скриптов по названию и пути, запуск на активной вкладке.
- Страница управления: создание/редактирование/удаление, вложенные папки, выбор родительской папки, дублирование скриптов, порядок соседних элементов кнопками ↑/↓.
- Выбор иконки: эмодзи/короткий текст или PNG/JPEG/WebP/GIF до 256 КБ. Изображения хранятся в JSON как data URL, внешние запросы для иконок не нужны.
- JSON-экспорт всей сохранённой полки. Импорт с добавлением или заменой, проверкой структуры и явным подтверждением замены. Импортированный код автоматически не запускается.
- Редактор CodeFlask: подсветка JavaScript, номера строк, тёмная тема и Tab с отступом в четыре пробела. Код сохраняется обычной строкой, без HTML-разметки подсветки.
- Защита несохранённого черновика при переключении и выходе, Ctrl+S / Cmd+S.
- Локальное хранение, версия формата и контроль ревизий: параллельное окно не может молча затереть изменения. При конфликте скопируй свой черновик и обнови страницу.

## Код и контекст исполнения

Пиши обычный **JavaScript** без `javascript:` и без обязательной IIFE:

```js
const links = [...document.querySelectorAll('a')];
console.table(links.map((a) => ({ text: a.textContent, href: a.href })));
return `Найдено ссылок: ${links.length}`;
```

```js
const response = await fetch('/api/profile');
return await response.json();
```

Само расширение написано на TypeScript; текст пользовательских скриптов исполняется как JavaScript, без TS-транспиляции. При запуске расширение внутренне помещает код в async-функцию: доступны `await` и `return`, локальные `let`/`const` не конфликтуют между запусками. Чтобы сохранить переменную глобально, присваивай её `window.myValue`.

Инъекция выполняется в **MAIN** верхнего фрейма через `chrome.userScripts.execute`, не через `eval` в popup. Доступны DOM и JavaScript страницы, но не привилегированные API расширения. Страница также видит код в MAIN; её CSP и поведение могут влиять на исполнение. Успешный `return` отображается в popup (до 4000 символов), исключение — как ошибка. `console.log` и подробные ошибки смотри в DevTools самой вкладки. Ошибки синтаксиса приходят от Chrome. Если скрипт возвращает незавершающийся Promise, popup продолжит показывать выполнение; закрытие popup не отменяет уже запущенный код.

Полка сохранится при закрытии popup. Если закрыть popup во время выполнения, скрипт не отменяется, результат в следующем popup не восстанавливается. Поиск и раскрытие дерева в popup действуют до его закрытия.

## Разрешения

- `storage`: хранение полки локально, без синхронизации с сервером.
- `userScripts`: исполнение введённого пользователем кода.
- `activeTab`: сведения об активной вкладке после клика по иконке.
- `host_permissions` для HTTP, HTTPS и файлов: необходимы для userScripts на выбранных страницах. Доступ можно ограничить через настройки Chrome. Автозапуска и фонового чтения страниц нет.

## JSON, версия 1

```json
{
  "format": "script-shelf",
  "version": 1,
  "items": [
    { "id": "tools", "kind": "folder", "parentId": null, "name": "Инструменты", "icon": "📁" },
    {
      "id": "title",
      "kind": "script",
      "parentId": "tools",
      "name": "Заголовок",
      "icon": "⚡",
      "code": "return document.title;"
    }
  ]
}
```

Порядок массива задаёт порядок соседей. При добавлении импорта все IDs переназначаются, ссылки на родителей сохраняются. При замене IDs сохраняются. Валидатор отвергает дубли IDs, отсутствующих родителей, циклы и неизвестные версии. Лимиты: 5000 элементов, 32 уровня папок, 1 млн символов на скрипт, 8 МБ на импорт; дополнительно действует квота `chrome.storage.local`.

## Структура

- `src/model.ts`: модели элементов, дерево, JSON-валидация и импорт/экспорт.
- `src/types.ts`: именованные литеральные типы для видов элементов, команд, режимов и формата.
- `src/guards.ts`: проверки примитивов, сужение моделей и проверка входных сообщений/результатов.
- `src/constants/values.ts`: значения дискриминаторов, лимиты и параметры выполнения; `symbols.ts` — символы интерфейса.
- `src/background.ts`: сообщения, сериализация операций записи, контроль ревизий.
- `src/runner.ts`: запуск пользовательского кода.
- `src/Popup.svelte`: popup и запуск на вкладке.
- `src/Manager.svelte`: управление полкой, черновик, импорт/экспорт.
- `src/components/ItemTree.svelte`: общее дерево и поиск.
- `src/components/ScriptEditor.svelte`: поля и редактор скрипта.
- `src/components/CodeEditor.svelte`: интеграция CodeFlask, синхронизация кода и тема подсветки.
- `src/vendor/codeflask.d.ts`: декларация используемого API CodeFlask.
- `src/components/ItemIcon.svelte`: отображение эмодзи/изображения.
- `src/components/AppHeader.svelte`, `StatusBar.svelte`: общая шапка и сообщения состояния.
- `src/popup.ts`, `src/manager.ts`: точки входа и `mount`.
- `src/ui.ts`: небольшие вспомогательные функции без ручного рендеринга.
- `svelte.config.mjs`, `rollup.config.mjs`, `eslint.config.mjs`: конфигурация UI и сборки.
- `public/`: manifest и статические ресурсы.
- `tests/`: проверки дерева, импорта, исполнения и хранения.

Документация API: https://developer.chrome.com/docs/extensions/reference/api/userScripts
